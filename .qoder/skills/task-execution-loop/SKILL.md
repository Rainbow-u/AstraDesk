# 任务执行循环

对 T00 至 T14 中的单个任务执行完整闭环。一次只处理一个任务；无外部阻塞时可直接进入下一个依赖任务，不反复询问确认。

## 执行步骤

复制此清单并跟踪进度：

```
任务进度：
- [ ] 1. 读取上下文，确认任务未实现
- [ ] 2. 写明输入、目录、验收用例、边界
- [ ] 3. 最小可运行改动
- [ ] 4. 运行风险相关测试与受控验证
- [ ] 5. 修复失败或标记 blocked
- [ ] 6. 更新 STATUS.md 与证据路径
- [ ] 7. 判断是否继续下一任务
```

**1. 读取上下文**
读 `AGENTS.md`、`docs/PRD.md` 相关章节、`docs/WORKFLOW.md` 第5.2节任务表中该任务行、`docs/STATUS.md`、相关 `contracts/` 与现有代码。检查 Git 状态，不覆盖无关文件或未提交改动。若任务已实现，直接核对验收证据后跳到步骤6。

**2. 界定任务**
写明：本任务输入与依赖、要修改的目录（遵守 AGENTS.md 目录归属）、对应验收用例（任务表"验收与证据"列 + WORKFLOW 第7.2节相关测试）、明确不做什么（阶段外功能不添加）。

**3. 最小改动**
优先复用已验证模块；实现决定属于小范围的直接做并记入 `docs/DECISIONS.md`；属于实质范围变化（改产品目标、放宽 B 门槛、移除核心模块）的停下交负责人决定。

**4. 验证**
运行与本任务风险直接相关的测试，外加一次真实运行或标注清楚的受控验证。遵守不可协商约定：mock/fixture 必须显式标识；真实模式不静默回退；未执行的测试记"未执行"。

**5. 处理失败**
修复直到通过。外部资源缺失（GPU、权重、密钥、授权照片）时，将对应检查标 blocked 并保存原因，先完成所有不受影响的工作。

**6. 更新状态**
在 `docs/STATUS.md` 追加完成报告（模板见下），更新"当前阶段、已通过任务、阻塞与下个任务"。契约有变更时同步 `contracts/`。已授权仓库可建立局部提交，不含密钥与用户照片。

**7. 继续判断**
下一任务无外部阻塞则直接开始下一循环；有阻塞则集中列出缺口后停止。

## 完成报告模板（WORKFLOW 6.3）

```text
任务 ID：T__
状态：done / blocked / in_progress
需求覆盖：FR__、H__（对照 PRD 第4、6节）
实现说明：两三句话说明实际完成的行为
变更文件：实际路径列表
验证命令：只写执行过的命令
验证结果：通过数、失败数、未执行项及原因
真实运行：输入样本ID、模型版本、结果记录路径
剩余限制：例如仍不支持堆叠或强透视
下一任务：T__及其所需输入
```

禁止在报告中出现密钥、令牌、用户隐私照片的公开链接。

## 阶段验收

任务完成触发 G0 至 G5 门槛检查时（WORKFLOW 第7.1节），逐项区分通过、失败、未执行、外部阻塞；关键验收按第7.3节保存完整证据包到 `artifacts/`。
