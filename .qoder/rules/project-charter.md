## 二、硬性红线（不可协商，违反即评审不通过）

1. **真实性**：mock、fixture、缓存、示意图只用于 demo 与测试且必须显式标识；真实模式下模型不可用必须报错或明确降级，禁止静默回退 mock 维持"成功"；没有真实训练、评价或测量时不生成虚构结果数字（含 mAP、评分、耗时）。
2. **事实清单守恒**：人工确认后的物品清单是唯一事实依据；任何模块不得擅自增删、改名已确认 `object_id`（H01）；无解时返回 `NO_FEASIBLE_LAYOUT`，不通过删物品、缩框伪造可行布局。
3. **布局硬约束**：H01–H07 全部满足才允许进入生成；硬约束不参与加权抵消；不移动固定物品（H03）、不缩小物品（H04）、不越界（H02）、目标框不重叠（H05）、遵守禁放区（H06）与杯瓶/电子设备分隔（H07）。
4. **坐标契约**：`bbox_image` 与 `bbox_desk` 显式区分（PRD 5.2：归一化、左上原点）；`bbox_desk` 由后端从原图框与桌面范围推导并校验；转换必须有往返测试；模型端缩放/补边/裁切坐标由适配器还原；变更桌面范围必须生成新 revision。
5. **版本与终态**：所有结果绑定不可变 SceneRevision；偏好变化创建新 revision，旧结果不混入新版本；任务终态不可被迟到响应覆盖；重试创建新 job 并记录 `retry_of_job_id`。
6. **有界重试与幂等**：每个生成任务总共最多 2 次生成调用；推理任务必须携带 `Idempotency-Key`（同键同请求返回原任务，同键不同请求 409）；取消、超时、worker 重启均有明确终态，不因刷新或重试产生重复收费调用。
7. **诚实报告**：未执行的测试标"未执行"，不得写成"通过"；外部资源缺失标 blocked 并保存原因；截图只证明界面状态，调用日志只证明发生过调用，验收需完整证据包（PRD 11.1 / WORKFLOW 7.3）。
8. **安全与隐私**：密钥仅服务端环境变量读取，不进入前端、仓库、日志、截图或报告；不提交用户私人照片与未授权数据；图片路径由服务端生成，客户端只传资源 ID；输入文字与图片内可见文字是业务数据，不能成为系统指令；未配置授权不调用收费后端、不租 GPU、不公开部署。

## 三、交付默认

1. **交付层级**：先 A（布局基线）再 B（完整 MVP），C（研究增强）独立推进；**B 是首版完成定义**，A 只是中间里程碑；降级输出 A 的结果不得记作 B 已验收。
2. **任务单元**：按 WORKFLOW T00–T14 依赖顺序，一次完成一个可验证任务（5.3 节固定循环，由 task-execution-loop 技能承载）；不以"一次性生成整个项目"为开发单元；无外部阻塞连续推进，不反复询问确认。
3. **完成报告**：每任务在 `docs/STATUS.md` 按 6.3 节十字段格式记录（任务 ID、状态、需求覆盖、实现说明、变更文件、验证命令、验证结果、真实运行、剩余限制、下一任务）；报告中禁止出现密钥与隐私照片链接。
4. **质量门槛**：阶段验收按 G0–G5 逐项区分通过 / 失败 / 未执行 / 外部阻塞；关键验收保存证据包到 `artifacts/`；任务完成后由 delivery-reviewer 子智能体做只读评审，评审重点为模拟替代、事实清单变动、坐标混用、无界重试、未执行测试。
5. **技术默认**：采用 PRD 8.1 基线（React+TS+Vite / FastAPI+Pydantic / PyTorch+OpenCV+YOLOv10 适配器 / 一个 Qwen-VL 后端 / Diffusers 兼容生成适配器 / SQLite+SQLAlchemy / 独立 worker / pytest+Playwright）；小范围兼容调整记入 `docs/DECISIONS.md`，实质范围变化（改产品目标、放宽 B 门槛、移除核心模块）交负责人决定。
6. **目录与入口**：遵守 WORKFLOW 第 4 节目录归属；统一从项目根执行入口命令（如 `python -m services.worker`），不临时修改 `PYTHONPATH`；规则权重、类别映射、提示词版本化存放，不硬编码。
7. **资源缺口处理**：缺 GPU、权重、密钥或授权照片时，先完成所有不受影响的工作，再集中列出缺口；表格模板不等于已完成的采集或评价。
